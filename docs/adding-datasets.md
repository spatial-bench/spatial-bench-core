# Add a dataset

Add generated inputs in core, then expose them through driver cases in the
bencher catalog. The current `dataset` tag selects `uniform` or `gaussian`
distributions for both construction points and query points.

## Define construction and query inputs

Specify coordinate scale, supported dimensions/types and the relationship
between construction and query sets. Include seeds and any clustering, duplicates
or ordering that affects the workload.

For a fixed real-world dataset, first define acquisition, licensing,
preprocessing, construction/query splits and a content digest. Importing files
requires a new input/provenance contract: the current generator accepts
distribution parameters rather than an arbitrary input file.

## Extend the shared generator

Implement the distribution in
[spatial-bench-dataset](../crates/spatial-bench-dataset/src/main.rs) and add its
name to the `dataset` vocabulary in
[vocab.rs](../crates/spatial-bench-core/src/vocab.rs). Existing generation uses
ChaCha8, with construction seed `s` and query seed `s.wrapping_add(1)`.
Scalar types consume the stream differently, so include the type when comparing
generated bytes. The public [methodology](https://spatial-bench.org/methodology)
defines the existing distributions.

The generator source defines the local binary format: a 29-byte header followed
by construction and query coordinates in native endianness. Preserve that format
when adding a distribution. If the payload or header changes, version the stream
and update every affected reader. Changes to `CaseSpec` also affect the harness
contract.

With the tools from [development setup](development.md) on PATH, inspect an
existing input:

```sh
spatial-bench-dataset --kind uniform --dims 3 --dtype f64 \
  --tree-count 4 --query-count 2 --seed 42 > /tmp/spatial-bench-input.bin
python3 - <<'PYCODE'
import struct
from pathlib import Path
raw = Path('/tmp/spatial-bench-input.bin').read_bytes()
assert raw[:4] == b'SBDS'
assert struct.unpack_from('=IIBQQ', raw, 4) == (1, 3, 1, 4, 2)
assert len(raw) == 29 + 6 * 3 * 8
assert all(0 <= x < 1 for x in struct.unpack_from('=18d', raw, 29))
PYCODE
```

## Add driver coverage

In [benchers](https://github.com/spatial-bench/spatial-bench-benchers), check readers
for hardcoded distribution or shape assumptions and add supported manifest
cases. `matrix.dataset` can expose several distributions. Add explicit selections
to `corpus.toml` if the input belongs in the Standard Corpus.

## Validate and propose the change

Add a deterministic generator test covering repeatability, decoded shape and
properties of the new distribution. Exercise supported scalar types and relevant
edge cases, including short/invalid data at reader boundaries. Floating-point
transcendental functions can vary by platform; scope byte-identity claims to
what has been checked.

Run the core checks and one small benchmark per affected driver/reader. Include
seed, expected input properties and run commands in the core and bencher PRs.
Update the public [methodology](https://spatial-bench.org/methodology) and
[coverage](https://spatial-bench.org/coverage). If new input identifiers or digests
must persist in results, coordinate schema, collation and web-reader changes too.
